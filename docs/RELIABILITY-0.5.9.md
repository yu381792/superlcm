# 0.5.9 可靠性修复

2026-10-04，基线提交 `8891819`。全面独立审查发现的 12 项问题已逐项修复并由原审查代理复核，相关本地复现未留下确认的阻断问题。

Claude 压缩边界现在要求唯一匹配，重复片段以及旧前缀已压缩的情况不能误删未摘要内容。Hermes 在镜像写入成功、数据库提交失败后恢复已写尾部，不再次追加同一行；损坏尾部保留并暂停。自动摘要使用独立任务归属、请求期间续期和保存事务内检查，设置改变后不继续旧批次。

DSH 的归档进程失败会显示异常并退避恢复，可用确认后重放已观察会话。查询工具使用同一档案库，设置更新取消旧草稿，摘要树检查接受合法内部节点，重建不再为每个来源重复扫描整份会话。通用摘要入口拒绝 DSH 会话，保持压缩插件为唯一摘要生成者。发行清单版本保持一致，更换 API 地址不会沿用另一个地址的密钥。

主会话执行 `npm run validate`，122 项通过；执行 `npm run test:dsh-runtime`，26 项通过。原独立审查代理执行相关测试 81 项通过，并再次复现重复消息边界、保存任务归属竞争及归档管道错误，均通过。所有故障注入使用本地合成数据，不购买模型调用。

这些检查确认了已发现问题的修复，不替代真实部署验收。真实压缩效果、后续缓存恢复、跨重启边界和跨平台运行需要分别观察。部署时先保护宿主仍拥有的长任务，再更新插件与重启服务；不能把文件已更新当作运行中的进程已经生效。
