# Issues #2–#4 修复与验证

2026-10-09，完整版 SuperLcm 源码版本 0.5.22。报告者 muxammadreza 确认 0.5.21 的流读取与压缩边界修复有效，并在真实使用中继续发现三项问题：[#2](https://github.com/yu381792/superlcm/issues/2)、[#3](https://github.com/yu381792/superlcm/issues/3)、[#4](https://github.com/yu381792/superlcm/issues/4)。本次不修改独立 `dsh-superlcm` 仓库。

## 修复范围

| 问题 | 实际处理 |
| --- | --- |
| 推理耗尽固定输出额度 | 可见输出量按原文语言密度估算；实际返回的推理字段或用量证明模型在思考，且达到长度上限时，最多补额重试一次。只记模型额度和长短比例，不记隐藏推理。 |
| 下一轮继续用相同不足额度 | 私有数据库按规范化端点、配置模型、思考程度的哈希保存预算；重开进程继续使用。不按模型名猜测能力。 |
| 完整摘要超长后整段失败 | 最多两次缩短重写，无进展提前停手；仍超长时发布明确标记的有限导航摘要，包含来源范围和查回原文要求。 |
| 被截断或空回答伪装成功 | 不允许进入重写或机械裁剪。API 终止原因、实际流完成证据、CLI 终止事件和宿主完成状态各自核实。 |
| 机械裁剪后的内容丢约束 | 降级标记向上继承、后台计数显示；Claude 接管拒绝使用这些摘要，保留宿主原生压缩。原始记录始终完整可查。 |
| 设置改变或写入权失效后继续请求 | 每次 API 请求，包括参数协商、推理重试和重写，都核配置与写入权。独立 CLI 重写和宿主内生成也核查，旧任务不能释放新任务的写入权。 |
| 原生回退原因不可见 | 会话后台与 `doctor-local` 显示最新原因码、解释、时刻和覆盖位置；区分拒绝和异常，成功或关闭接管会替换旧状态。 |
| 错误详情暴露上游内容 | HTTP 正文、网络异常、解析异常和任意上游模型字段不反射到用户诊断；仅记录受限状态与数字用量。 |

摘要生成正常时没有额外重写调用。最坏情况下，一次原始生成、一次有证据的推理补额、两次长度重写；接口参数兼容协商另限一次。API 共用一个截止时间。CLI 单次生成仍有原有的时间和输出大小边界，并由写入权续租保证不会与另一后台任务重复执行。
