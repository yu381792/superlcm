# Issue #1 修复与验证

2026-10-08，版本 0.5.21。问题来源：[GitHub issue #1](https://github.com/yu381792/superlcm/issues/1)，感谢 muxammadreza 的复现和修复建议。

## 修复结果

| 场景 | 修复后的行为 |
| --- | --- |
| 最后已覆盖消息与第一条未覆盖消息之间只有工具空消息 | 合并为同一个可见边界，保留较早位置，再按完整用户轮次处理工具组。 |
| 真正重复的可见消息产生多个可能边界 | 保留原生回退，不用最近原文包绕过歧义。 |
| 原生摘要被算成用户新提问 | 从校验过的归档记录核实 `isCompactSummary`，只在该摘要本条已被分层摘要覆盖时允许替换。 |
| 用户引用相同摘要开头，或相同的截断前缀 | 出现普通用户记录的匹配证据时保留用户消息；不能确定就回退。 |
| 导入从原生摘要或会话中段开始 | 不推断缺失的旧历史已被覆盖；未覆盖的原生摘要保留。 |
| OpenAI 兼容路由返回 `text/event-stream` | 组装事件内容，支持 CRLF、多行数据、跨字节分片、文本数组及用量帧，选取第零个回答。 |
| 流损坏、读失败、上游错误、未完成或输出过长 | 拒绝入库，保留原始记录；不会把部分文本当成完成摘要。 |
| 空回答或非空 `in_progress` 回答 | 即使 HTTP 成功也拒绝，显示配置模型和受限枚举的结束状态。 |
| 后台进程隐藏标准错误输出 | 安全诊断持久化，并在会话后台失败提示中显示；新增原文不清除失败，成功重试才清除。 |

错误详情不反射上游任意 `model`、`finish_reason`、错误正文、部分回答或凭证。既有 JSON 摘要接口、Anthropic 非流式接口，以及 `max_completion_tokens` 重试仍保留。
