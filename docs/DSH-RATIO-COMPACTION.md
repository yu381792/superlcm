# DSH 比例压缩

默认接入仍由 DSH 原生压缩。本文描述「压缩 → DSH → 由 SuperLcm 接管压缩」打开后的策略。独立后台档案摘要和 Claude 的可选接管设置保持各自配置。

## 准备与替换

- 平时以约 20K **原文输入**为一批准备摘要。粒度可改，工具调用和结果作为完整组，实际批量可能略超目标。小窗口会自动缩小批量。
- 默认至少四个同层相邻摘要（高级设置可调整）、且合并输入达到最低量时，做常规合并。常规只把叶摘要提升一层。超过整体摘要预算才进一步合并，避免每追加几句话就反复重写旧摘要。
- 可用输入容量的 70% 是预算收口点。旧摘要与新摘要共同收紧到最终摘要预算。80% 固定当前可压范围，准备齐全后只做一次上下文替换。80% 后新到的原文留在下一轮，不反复扩张本轮范围。
- 90% 是安全等待区。后台未就绪时最多等待 30 秒，仍不够时停止本次派发并保留已接纳输入，用户可等待或调整配置后继续。

## 容量和保留

真实主请求已经绑定的适配器容量优先于随后修改的供应商元数据。可用输入容量是该窗口减去实际请求的输出预留。系统说明、工具定义、旧摘要和原文都占预算；摘要模型的窗口不用于主会话门槛。

常规近期原文目标约为可用输入容量的 4%，在约 2K 到 64K 之间，并为小窗口进一步缩小。完整最新用户轮次和工具边界优先，即使因此保留更多原文。自动上下文快照不冒充最新用户输入。

压后目标约为输入容量的 10%。摘要目标最多约 6%，还需扣除系统、工具和近期原文成本。它是估算目标：当前用户轮次很大，或门槛之后新增了大量原文时，实际压后输入可能更大。选区按供应商已报告的用量校准文字估算；这不会被标成供应商真实 token 用量。

## 提交、恢复和费用

准备和合并只写独立草稿，不改变 live surface。主请求在宿主接纳新输入、记录实际路由和工具后接受最终检查。提交改变 surface 时，宿主通过专用本地重建信号重新形成请求，旧冻结请求不会发送给适配器。

草稿保存选区、逐事件内容哈希、树引用、设置和模型身份。恢复及提交都验证原文、连续范围和工具配对。切模型或改策略使不匹配草稿失效。已完成叶批可在合并失败后继续复用。

摘要没有省下空间时，记住具体输入、目标、路由和策略。冷却结束或重启不会再次购买相同失败调用。暂时的网络或服务失败仍按递增冷却重试。极小且连空摘要检查点都装不下的尾段明确保留原文。

完整原始记录始终存档。摘要需要保留当前目标、已改变的决定、未解决事项及引用；需要精确结论时仍应查原文。

## 兼容与验证

旧明确指定的固定 token 配置仍可在代码级使用。控制台保存改用比例模式。正常重新接入采用摘要接入、关闭接管，并将旧固定门槛迁移为比例策略；已是比例模式的粒度保留。

自动测试使用安装中的 DSH 原生服务与真实 Agent.send 流程，模型返回使用本地桩。覆盖准备期间前缀稳定、单次替换、百万窗口、路由变化、已绑定容量、超大新输入、整轮保留、树引用、草稿恢复和无进展费用。真实模型摘要的内容质量还需要任务回放来评估，测试结果不会被称为“智力无损”。
