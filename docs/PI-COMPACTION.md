# Pi 后台摘要与直接替换

SuperLCM 默认沿用主模型及账号，在后台分支一次写出分块、上层摘要与根节点，主会话继续工作。独立 API 模型作为高级选项保留。正常到80%时，只读取、校验并装入已经完成的摘要；冷恢复或真实容量不足时，在发送前等待后台准备。

## 实际流程

1. 达到约70%后，扩展从 Pi 正式提供的模型可见记录里选取可压缩的旧前缀，在后台保留原请求前缀、追加整树摘要指令。最近对话按 Pi 的 `keepRecentTokens` 保留。长工具链可以在已闭合的工具组之间选边界，当前完整用户请求另外原样保留。
2. 后台准备期间，模型和工具照常执行。准备、等待及仅完成草稿时保持静默，完成结果保存在 SuperLCM 数据库。后来追加的消息留在原文尾部，不会使已完成前缀失效。
3. 达到80%时，扩展在 `turn_end` 的正式边界条目接口返回一个压缩条目，Pi 自己保存并重建模型上下文，原工具链接着执行。请求内替换时，近期系统指令与对话按原有顺序保留。此过程不调用 `ctx.compact` 中断正在执行的任务，也不再次生成摘要。
4. 空闲会话、手动压缩与原生溢出恢复通过 Pi 的 `session_before_compact` 接口安装同样的结果。优先只读成品；明确手动请求、原生溢出或容量不足而没有成品时，等待已有后台任务，必要时准备一次恢复摘要。使用本次压缩的取消信号，不沿用已失败前台请求的信号。

自动通知只显示真实失败，或在核对原生检查点已经写入后显示一次压缩成功。压缩后的主模型回执已到时，提示使用 Pi 根据回执计算的当前用量；尚无回执时显示 `压缩前约 405K，压缩后待模型回执`，不把本地估算冒充实际用量。下一次模型请求完成后，Pi 的上下文窗口会显示新的用量。未安装的草稿和仅归档的完成结果保持静默；失败的分支每次实际失败只报一次，后台诊断记录继续保留。

如果生成还没完成，安全范围内继续保留原文并运行前台，跨过目标比例本身不会阻塞安全请求。主模型分支的临时故障独立重试，等候时间从1分钟逐步增加、最长5分钟，不依赖新输入。上游明确拒绝重放、无效完整摘要和不支持的请求格式会停止自动重试，显式手动 `/compact` 可重新尝试。输出被截断则改选更小的完整前缀。已生成摘要遇到数据库忙或保存超时，只重试保存，不重复调用模型；语义校验拒绝保存会直接停止。独立 API 路线的失败冷却最长16分钟，在后续会话活动中重试。更换模型或设置会清除旧配置的等候限制。切换模型、修改旧消息、换分支或更改摘要配置时，不复用失效的摘要。普通追加不作失效处理。

## 容量保护

正常情况下70%准备、80%替换。另设容量保护：系统提示、工具定义、最近原文、新输入、图片和模型输出预留都计入预算。发送前按剩余空间限制本次输出额度，模型配置保持不变；只有确认空间不足时才提前等待摘要。

如果选中的旧前缀加上固定提示、工具和摘要指令仍放不下，发送前改选更早的完整消息边界，并实际缩小发送的前缀；未选部分仍是前台原文。缩窄步长跨过了可用边界时，改试前一个完整边界。合法思考所需的输出空间不足时也走缩窄流程，思考参数本身非法则报错停止。此类本地容量拒绝不等待一分钟再重试同一份请求。最小完整消息组也放不下时提示一次并停止无效重试；原文前缀、工具、固定请求内容、模型或设置变化后可以重新准备。

部分订阅中转不支持输出上限，实际会在转发时移除该字段。完整成功回执即使超过本地临时缩小的额度，只要输入、缓存输入与全部输出仍在安全窗口内，且输出未超过原始请求额度，就继续核验和保存完整摘要。摘要树结构、来源与最终续接容量仍分别检查；缺少安全回执则立即缩小前缀，超过原始输出额度则明确停止。

冷恢复会查询已经完成的较早前缀摘要，在重新核对来源、完整边界和设置后使用，不因重启后的默认切点不同再生成一遍。来源或设置不一致的成品不复用；容量不足或格式有问题的成品也不会再次自动选中。

接近安全上限而摘要仍未完成时，暂停下一次模型请求，等待已经启动的后台工作。独立 API 路线的等待总时限为三分钟；主模型分支失败时按间隔重试，等待持续到成功或会话取消。请求格式捕获单独设置30秒时限，取消或超时后不再接收迟到结果。旧摘要覆盖不足时最多重新准备一次。摘要失败或最近工具结果本身过大时，中止本轮并保留原文。发送前还对实际消息、工具定义以及请求中实际的输出预留复核；不安全请求在 provider 边界抛错并触发 Pi 的中止信号，不发送给供应商。空闲时需要等待容量恢复的新输入会先保存在原生会话的 `superlcm-deferred-input` 条目中，恢复成功时继续提交；被拦住时需要恢复后重新提交，界面会明确提示。在途 steering 和 follow-up 输入始终交给 Pi 原生队列，不进入这条空闲输入拦截路径。

切换会话会取消旧等待。旧查询、旧模型及旧替换回调不能清除新任务，超时或取消后晚到的响应不参与替换。关闭压缩接管时，归档步骤仍允许后台分支运行。

这些预算使用文本估算，图片单独预留空间，不把图片的base64编码当文字。同一模型的历史请求已收到真实用量、且后续没有修改该历史前缀时，用已核验的用量回执校准旧前缀（包括删除失败轮次的 `context_edit` 之后，以及冷启动或后台分支重放时），只对新增内容及变化的工具、系统等字段作保守估算；已完成输出和思考摘要不重复计数，Pi 仅用于界面的工具 `details` / `nestedCalls` 不计入模型窗口。OpenAI Responses 的加密思考内容（含 `openai-completions` 包装下实际走 Responses 的同模型响应）只有在请求中的项目和同一模型的原始响应完全一致、且原始响应有有效用量时，才按该次思考用量预留；同一响应的多块思考共同使用这份预留。来源不明、内容改变、回执无效或其他格式仍按原来的文本估算。Pi 设置禁止图片时，后台请求也将图片替换成原生占位文本；切换该设置会使旧捕获和未安装草稿失效。最终准确用量由供应商报告。

## 配置

本地后台打开 `http://127.0.0.1:8791/#connect`，在 Pi 卡片选择“主模型后台分支”。关闭压缩接管仍会独立保存后台摘要；需要替换上下文时，再到“压缩 → Pi”启用，默认80%。自定义比例11%–99%，摘要始终提前10个百分点准备，例如50%替换对应40%准备。开启“允许其他模型”可从 Pi 自己的供应商和模型列表选择后台模型；聊天模型不变。

```sh
node src/cli.js setup pi --apply
node src/cli.js pi-policy --enable --summary-mode main-fork --ratio 0.8
node src/cli.js pi-policy
```

高级独立 API 模式可显式传入 `--summary-mode api --api-ref <已保存模型编号>`。关闭接管不会删除摘要方式。主模型分支不需要独立模型凭据；配置有误时不自动改用 API。

运行时代码更新后，已在工作的 Pi 进程等当前任务结束，再重启并恢复原会话。本机安装版 Pi 的 `/reload` 可能沿用缓存的底层 JavaScript 模块。

`context_with_system` 只标记当前请求。在 Pi 模型注册表返回的有效 provider 上临时包装 `streamSimple`，等原有 `onPayload` 完整执行后，再捕获和检查最终请求。后台通过同一模型注册表发送，重跑完整请求处理链，连同新增摘要指令和来源锚点一起处理；同模型分支继承已经处理的请求头。选择其他模型时使用其原生转换和凭据，不复制主模型请求头；后台不会执行工具。包装在会话结束时恢复，不修改供应商登记、全局配置或安装版 Pi。Google 和 Pi 原生消息接口按各自的请求结构保留前缀，输出限额也按实际字段检查。遇到无法识别的请求结构时会提示并停止重复重试，模型或设置变化后再尝试。`pi-ready` 始终只读；`session_before_compact` 的恢复准备条件见实际流程第四项。

## 接入边界与本轮整理

Pi 1.5 的 `ctx.compact()` 会先中止当前任务。因此运行中的 `turn_end` 条目提交与空闲时的原生压缩回调暂时保留；两者使用同一份已验证结果。运行中提交统一经过一个条目构造函数。冷恢复必须先改变本次请求，再在回合边界落盘；取消前台生成只取消后台工作，不清掉已经用于请求的待提交摘要，终止回合也会核对来源并提交。会话切换仍清除全部旧状态。

完全改成单一 `session_before_compact` 入口，需要同步管理每个模型的原生压缩阈值，以及处理原生阈值检查之后才加入的大输入和工具。本轮没有靠修改全局设置或安装版本内核实现这一点。归档、完整边界、历史摘要树和来源验证保持不变；主要整理生成与保存的职责，删除一层重复超时与重复边界提交代码，修正消息排队、原生恢复和取消收尾。随后将请求容量检查、冷恢复与替换集中到完整请求处理链之后，修复了后置脱敏遗漏，具体边界见文末。

## 验证范围

`npm run test:pi` 检查来源映射、工具闭合、失效、容量保护和事务。`node scripts/verify-pi-compaction.mjs --main-fork` 使用本机 Pi SDK 和本地假供应商，验证70%后台准备、主工具链继续、80%原生边界替换、零替换阶段摘要请求，以及新增用户和工具原文保留。这些场景在安装版 Pi 1.5.0 与隔离本地供应商验证，用量回执才是实际供应商缓存命中证据。

`--late-redactor` 验证后置脱敏覆盖前台、后台及摘要指令，和 `--cold-input` 合用验证冷恢复；这些安装版 Pi 回归已加入 `npm run test:pi`。后置超大工具、输出改写和独立 API 场景也纳入自动测试。

新增 `--queued-input` 验证在途指令实际进入后续请求，`--native-overflow` 验证原生压缩后自动重试，`--cold-input --abort-after-replacement` 验证取消后压缩记录仍落盘，均与 `--main-fork --full-window` 合用。

本轮容量、慢响应、异常摘要、重试和切换边界的实测见[故障审查记录](SAFETY-AUDIT-20261024.md)。`node scripts/verify-pi-compaction.mjs --main-fork --full-window --foreground-during-summary` 专门验证摘要尚未完成时前台下一请求已经发出；供应商和摘要响应均由本地模拟服务提供。

## 请求处理链的安全边界

2026-11-04 已修复后置脱敏遗漏。原先在处理中途捕获、再直接发送分支，可能绕过后续扩展。现在记录的是 provider 原有的完整处理回调，后台和请求替换都经过它；最终容量保护在回调结束后执行，扩展追加的大工具也无法绕过。拒绝发送的错误从 provider 边界抛出，不会被扩展事件分发器吞掉。异步处理期间切换会话的结果会被丢弃。

启动后尚未捕获完整处理链时，不盲发后台请求。已有可核验成品仍可安装；没有成品的首次手动 `/compact` 会明确提示先正常输入，首个主请求在最终发送边界恢复。找不到有效 provider 边界时保留原文并报错。实现按安装版 Pi 1.5 验证；自定义 provider 必须履行 Pi 的 `onPayload` 调用契约。

自定义比例与其他模型的真实 SDK 验证：`node scripts/verify-pi-compaction.mjs --main-fork --other-model --ratio50`。
