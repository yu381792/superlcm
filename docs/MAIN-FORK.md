# 统一主模型后台分支（0.6.0）

## 用户入口

控制台有“对话 / 工具 / 压缩 / 设置”四个主入口。工具卡片选择“主模型后台分支”（默认）、“独立摘要模型（高级）”或“关闭”。“压缩”页统一配置 Claude Code、Pi、dsh 的比例和可选后台模型，工具卡片仍管理摘要方式。明确保存过的 API 与关闭状态不会被升级覆盖。

| 工具 | 主模型后台摘要 | 可选接管 | 分支来源 |
|---|---|---|---|
| Claude Code | 支持，需本机 CLI | 支持 | resume + fork-session，继承登录与当前模型 |
| Codex | 支持，需本机 CLI | 由宿主负责 | app-server thread/fork + turn/start |
| Pi | 支持，实时扩展 | 支持 | 公开请求钩子与同一模型注册表 |
| dsh | 支持，实时插件 | 支持 | 最终原生请求与同一供应商服务 |

Pi 和 dsh 关闭接管后仍可后台生成并保存摘要，不改变当前上下文。两个 dsh 分发包均实现同一协议，但不应同时接管同一宿主。已经取消的接入不因升级重新开启。Claude 未安装时不应声称已完成真实宿主验证。

## 一次准备整棵树

1. 准备点始终比压缩替换点提前10个百分点。默认70%准备、80%替换；自定义50%则40%准备。按当前模型可用输入容量计算，页面支持11%–99%。固定安全源前缀，留出最近原文及当前用户约束；完整工具组不能拆开。旧 Claude 绝对 token 配置在保存新比例前仍按旧方式工作，CLI 的绝对门槛参数保留兼容。
2. 插件按约20K估算 token 的粒度指定叶片和精确源锚点，按四子节点扇出预先列出所有父节点，追加一次整树指令。阈值、粒度与归属由插件决定。
3. 默认分支保留原模型、账号、请求前缀和设置。在“压缩”页开启“允许其他模型”后，可从对应工具的真实目录选择后台模型。Claude 只在分支 CLI 增加 `--model`；Pi 使用原生模型注册表；dsh 使用配置的原生供应商和账号。聊天模型不变。其他模型必须容纳完整分支，容量未知或不足时保留原文，不裁剪对话来适配。选择其他模型时使用该模型的原生请求转换，缓存以用量回执为准。模型一次返回每个计划节点的摘要；后台不执行工具。Claude/Codex 原生协议与 Pi/dsh 请求接口不同，因此需要各自适配。
4. 检查来源、顺序、语言、预算和树完整性。少块、错误、工具调用、截断、取消、设置改变或源篡改均拒绝提交。全部节点、来源引用和用量回执一起提交；原文始终独立保留。
5. Pi/dsh 正常在所设替换比例（默认80%）安装已准备根节点，保留后来追加和最近原文。替换入口不生成摘要。安全容量不足但准备失败时阻止继续发送超限请求。Claude 无安全覆盖则交回原生压缩；分支模式不再启动旧同步补救。

容量检查还包含系统、工具、图片、新输入和模型输出预留，必要时提前准备或暂停。未知窗口不启动推测性的自动原生分支；手动后台生成可显式请求。

## 分块与调用次数

正常准备点前持续归档。到准备点后，一次任务固定一段旧原文，一次模型响应返回该范围的整棵树。分块数和摘要层数都不增加这次任务的请求次数。模型只需响应一次，插件负责核验和保存。

DSH 主模型分支按原文粒度保存不可变分块。后续分支复用已有分块，同层相邻分块达到设置中的合并数量时，在同一次响应中写父摘要，并继续逐层归并。未满组的分块保持原层。供主对话替换的滚动总览单独生成，不能作为下一轮的新原文块反复加层。旧总览保留并可搜索，页面只单列当前总览。旧档案的层级可根据已有关系重新识别；没有实际生成的父摘要不会凭空补造。

若旧版粗摘要还包含子块未覆盖的原文，不能只取它的子块继续归并。这种检查点完整保留为一个不可变的「旧摘要块」，其旧关系和原文仍可查询；后续与新增块正常归并，不会每轮再次套壳。

“一次”按成功任务计算。后续新的可整理范围、任务重试、来源或设置失效可能产生另一次分支。容量保护可以早于正常准备点启动；如果新增内容使已完成摘要仍无法腾出足够空间，当前请求会暂停，后台可以扩大覆盖范围重新准备，核验通过后再替换。独立 API 高级模式保留分批生成逻辑。

Claude 在宿主压缩后继续准备时，如果旧原文不再保证存在于分支上下文，插件会把经过核验的完整归档片段补充给分支。准备和保存时会核对宿主转录与归档；来源变化或压缩标记尚未归档时不提交。旧版缺少这项来源证明的 Claude 摘要仍可查阅，但不用于接管。补充内容按可用容量分批；单条无法完整表示或装入时不截断充数，也不将其标记为已覆盖。每批推进后可继续准备下一批。模型分支只有在十分钟没有有效输出时才会超时；持续输出时可继续完成。

## 缓存与失败边界

保留前缀有利于复用缓存，不保证命中。缓存读、缓存写和输出以供应商实际 usage 为准；更换模型、路由、缓存过期及供应商隐藏内容都可能影响命中。替换上下文产生新前缀后，需要建立该前缀的缓存。

摘要请求失败不修改原文，不自动改用独立 API，不在替换时重新购买摘要。配置变化、分支变化、原文变化和跨进程归属由快照、租约及事务检查保护。正常追加不使已准备前缀失效。

## 可重复验证

- `npm run check`：源码、生成页面及扩展的语法。
- `npm run test:main-fork`：完整树、迁移、两个原生协议、来源变化、取消、单生产者，以及 dsh 实际宿主的主动与被动摘要。
- `npm run test:pi`：Pi 来源映射、容量保护、配置事务和替换。
- `node scripts/verify-pi-compaction.mjs --main-fork`：Pi 1.4.0 的真实 SDK + 本地假接口，确认70%后台准备、连续工具链、80%原生边界提交、新增原文保留、替换时零模型请求。无付费接口。
- Codex 已验证真实本地 app-server 的持久会话临时分支与继承模型，不发起付费生成。Claude 本机未安装，仅完成隔离协议验证。

离线供应商返回的缓存计数只能验证回执传递，不能证明实际缓存命中率。全部历史套件的当前状态在[本次验证报告](MAIN-FORK-VERIFICATION-20261024.md)中单独记录，不能用分支专项通过代替全量通过。

新增故障复现、修复和测试边界见[容量与替换审查记录](SAFETY-AUDIT-20261024.md)。

## 比例与其他模型验证（2026-10-24）

`node scripts/verify-pi-compaction.mjs --main-fork --other-model --ratio50` 使用 Pi 1.4.0 和本地接口，确认40%准备、50%替换、真实注册表选取其他模型，主模型保持不变，替换阶段零摘要请求。DSH 的真实宿主测试覆盖50%/40%、其他模型和关闭接管时的后台分支。Claude 本机未安装，仅验证原生参数、比例配置、恢复及分支协议，未声称真实 CLI 实测。
