# DSH 关闭接管后的原生压缩修复

0.5.12 的全局接入停用了 DSH 原有的 `compaction-basic`。关闭 SuperLcm 接管只把自动开关设为 false，运行中的服务仍是 SuperLcm，压力监听和超限重试全部跳过。归档仍在线、设置确认已生效，均不能证明原生压缩可用。

0.5.13 在公开插件入口管理唯一压缩服务。接管开启时使用 SuperLcm；关闭时装载宿主提供的 `BasicCompactionEngine`，开启自动压缩及溢出恢复，摘要使用当前会话已路由模型。原生门槛与近期保留按宿主窗口、输出预留和原生默认策略计算，不继承 SuperLcm 的专用模型或绝对词元参数。SuperLcm 归档与设置服务常驻。

切换时取消旧压缩并等待其事务结束，随后卸载旧服务、加载新服务。固定的事件分派入口避免事件调用已取到旧监听列表后错过新引擎。取消包装及时拒绝不响应取消的模型结果；迟到结果被消费但不能提交。SuperLcm 摘要完整保留第四参数中的来源范围与树节点身份。

所选接管服务启动失败时恢复原生保护，但不将失败配置确认成已应用。相同失败配置只尝试一次，避免反复重建原生服务、重置其超限重试计数。配置变化后可以重新尝试。

本次测试使用已安装的 DSH 服务、会话投影、词元计量与真实原生压缩实现，模型回复为本地固定内容；不写生产会话、不调用供应商。新增测试覆盖关闭状态启动、自动压力压缩、原生手动压缩、超限重试次数、重复切换、切换期间正在进入的请求、忽略取消的迟到回复、后台草稿取消、来源元数据转发及启动失败回退。代码测试不能替代用户生产模型的摘要质量评价。

验证结果：基础检查与测试 141/141，DSH 宿主测试 45/45，其中新增所有者切换测试 8/8。独立审查发现的失败配置确认和原生重试计数重置问题已修复，原审查席定点复核关闭。
