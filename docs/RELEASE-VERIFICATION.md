# 发布前验证

发布者负责完成验证和独立复核，用户反馈用于发现尚未覆盖的问题。不能把用户的实际任务当作主要测试方法。完整验证入口：

```sh
npm run verify:release
```

任一阶段失败即停止发布。该命令检查源码与回归测试、真实 DSH 服务的压缩生命周期、实际 npm 安装包中的 CLI/MCP 和摘要运行，以及打包文件和本地引用是否齐全。临时数据库和合成对话与生产隔离，模型响应由假模型提供，不调用付费模型。

本轮增加的故障场景包括：正常结束标记缺失、未知结束原因、截断、取消、重复终结、终结后继续输出、工具调用输出；失败工具结果与请求共同分段，包含并行工具；文本导入中的用户与助手使用不同语言；失败批次在进程重启后的退避、暂停及显式恢复；四种 CLI 子进程忽略终止与输出超限。已有测试继续覆盖设置变化、迟到结果、租约竞争、数据持久化、来源冲突、树重建和精确原文召回。

同时发布 DSH 独立版时，两仓库分别运行 `npm run verify:release`，另运行：

```sh
node scripts/check-shared-core.mjs <DSH独立版仓库目录>
```

这项检查比较共用的摘要策略、语言识别、模型流终结和树提交模块，避免一版已修、另一版漏改。各自独有功能仍需各自测试。发布后核实实际运行版本、配置保留与安装文件，已有宿主进程未重新加载时明确说明。

## 本轮修复与重试规则

DSH 接管与独立后台摘要均需真实 `stop` 终结，异常输出不能替换上下文或存为完整摘要。已准备但尚未提交的旧策略草稿失效；已提交历史和全部原文保留。

完整版自动后台摘要按会话、批次与设置版本保存失败状态。相同失败批次先等待 5 分钟，后续失败延长等待；三次失败后暂停该批次自动重试。后续新消息不解除同一失败批次的限制。修改模型/摘要设置、产生不同批次，或显式“生成摘要”/CLI `summarize` 可重新尝试。取消与设置变化不记作模型失败，迟到结果仍拒绝。成功后清除对应失败状态；等待期间保留原错误，不能显示为已恢复。

## 验证范围

本轮真实安装与升级在 macOS、DSH 0.2.1-alpha.1、Node.js 22+ 完成。使用含中文、空格、`#` 和 `%` 的隔离路径。实际 npm 包也会解包到特殊字符路径后运行。GitHub Actions 按用户要求保持关闭；没有本轮 Windows/Linux 实机运行结果。测试不等同于所有模型在所有对话中都忠实保留结论，不作“没有任何 BUG”的保证。开发者负责补足可复现故障和新适配器回归，并在发布说明里列明覆盖范围。
