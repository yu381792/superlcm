# DSH 压缩优化（0.5.1）

结论是保留 DSH 原生引擎，补齐长期会话治理。统一 SuperLcm 仍只有一个
DSH 压缩引擎，摘要生成仍走 DSH 已配置的模型，共享归档不会再生成一遍。

## 插件性质与对照

旧 dsh-superlcm 是 DSH 的 `BasicCompactionEngine` 子类，作为唯一
`ctx.compaction` 服务接管压缩。它把选中的上下文替换成检查点，并把已成功
提交的摘要及原事件指针写入索引。完整事件由 DSH 保存，统一版另行归档供其他
载体读取。它具有后台准备、工具调用配对保护和精确原文召回能力。

Lossless Claw 则接入 OpenClaw 的上下文引擎接口：由宿主提供会话、模型调用
和生命周期接口，它维护原文及摘要关系，并在请求前组装摘要与近期原文。
两者的宿主接线不同。对照源码固定为
[`e05d8d34b2a44fdef556ce95dd90115b46630200`](https://github.com/Martian-Engineering/lossless-claw/tree/e05d8d34b2a44fdef556ce95dd90115b46630200)，
该源码的包版本为 1.1.1。

值得借鉴的是它的
[同层摘要合并与摘要前缀预算](https://github.com/Martian-Engineering/lossless-claw/blob/e05d8d34b2a44fdef556ce95dd90115b46630200/src/compaction.ts)
以及
[模型失败后的暂停重试](https://github.com/Martian-Engineering/lossless-claw/blob/e05d8d34b2a44fdef556ce95dd90115b46630200/src/compaction-guards.ts)。
实现重新按 DSH 的事件协议写，没有引入另一套会话数据库或另一个摘要生成器。

## 已改行为

以前优先冻结全部旧检查点，只有达到硬上限且后面的原文无法再压缩时才合并。
现在先检查旧摘要占用的预算；超预算时选择连续同层摘要，优先处理较浅的一层，
生成高一层摘要。正常至少四个来源，真实硬压力下允许至少两个。系统消息和后面的
近期原文不进入这个合并选区。每次仅处理一个有效选区，后续回合继续处理剩余压力。
未超预算时不扫描旧摘要关系，也不改稳定前缀。

后台任务的主人改为会话。同一会话即使被两个智能体使用，也只有一个生成或等待
提交的任务。每条模型路线独立记录失败；封禁、认证失败等情况至少等五分钟再试，
已有显式备用路线仍可使用。普通错误按 30、60、120 秒等间隔延后，最多达到
基础间隔的 16 倍。生成的摘要没有节省空间时，也不会下一回合立即重复购买一次。
修改引擎运行设置会清除等待状态，便于修复配置后重试。

后台生成有超时取消信号。若提供方尚未响应取消，原任务仍占用该会话的位置，
直到它真正结束；迟到结果不会提交。这样可避免靠放弃旧请求来制造第二个并发请求。
超时、失败或选区失效都不会写出成功压缩记录。只有选区、价格及工具边界仍匹配，
而且结果确实变小，才连续提交压缩事务。完整原文及已有子摘要始终保留。

## 新参数

`summaryPrefixTargetTokens` 默认 0，表示自动使用
`min(foldBatchTokens, softActiveTokens / 2)` 作为旧摘要预算。
`condensedMinFanout` 默认 4，是正常合并的最少来源数量；正常选区还需达到
`min(pressureFoldTokens, foldBatchTokens / 4)` 的输入规模，避免为很小的摘要
频繁调用模型。真实硬压力可放宽到两个来源。
`summaryTimeoutMs` 默认 180000，是整次后台生成的取消期限；
`summaryRetryCooldownMs` 默认 30000，是普通失败的基础等待时间。
这些参数不会改动原来选定的主、备用模型。

宿主明确报告上下文溢出时，按硬压力重新选区，不把估算占用数字伪装成硬上限。
若原文尾部自身太大、模型不可用或暂时没有可安全提交的结果，保留宿主错误与原文。
当前版本不通过截断原文或把失败标记成成功来宣称压缩完成。

## 验证范围

`npm test` 验证共享归档、回接、原文校验、压缩策略及等待重试状态。
`npm run test:dsh-runtime` 在已安装的 DSH 0.2.1-alpha.1 中使用真实会话、
原生占用估算和压缩基类，配合本机确定性的模型响应，验证四个叶摘要合成高一层、
原文逐条读回、两个智能体只发一个请求、封禁主模型后使用显式备用模型、
失效选区不提交、没有缩减不立即重试、超时迟到结果不提交。
这些验证不调用收费模型，不读写生产 DSH 会话，也不代表实测了在线模型的摘要质量。

另外以只读方式回放了 52 个真实历史会话的 1137 条已保存摘要正文，使用 DSH
原生会话与占用估算。正常预算下有 8 个会话出现可分层合并的选区；模拟溢出时
有 25 个会话出现可合并选区。原摘要内容没有更改，没有生成摘要或提交压缩。
这是历史摘要正文回放，不能当作完整生产会话或在线模型质量测试。

安装包与配置可以更新到等待生效的状态；现有 DSH 服务的重启仍按工作区规则单独授权。
