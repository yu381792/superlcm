# dsh harness 接入

dsh harness、Claude Code、Codex 等载体现在使用同一个 SuperLcm 项目和共享档案。
SuperLcm 插件独占 dsh harness 的压缩接口，负责压缩策略、摘要生成和上下文替换；
归档保存完整原始事件和已提交的摘要，不运行第二个模型。dsh harness 会话禁止 SuperLcm 的通用摘要任务，
即使全局摘要设置改变也不会重复生成。

0.5.1 增加旧摘要分层合并、按会话独占后台任务及失败后的等待重试。
设计对照、参数含义和验证范围见 [压缩优化说明](DSH-OPTIMIZATION.md)。

## 压缩由谁负责

由 SuperLcm 插件接管 dsh harness 的压缩。插件选择旧内容，在后台生成分层摘要，
替换上下文，并把完整原文和摘要存入共享档案；它通过 DSH 已配置的模型服务调用
模型，复用 DSH 的模型账号和上下文接口。这里不是仅给 DSH 自带压缩做归档。

## 控制台入口

「设置 → 压缩」已恢复为仅包含 Claude Code 的原有设置，不展示 DSH 控件、载体
能力列表或后台任务。DSH 的接入在「接入 → dsh harness」。接好后，在 DSH 界面的「插件 → SuperLcm」
管理接管开关、模型、压缩门槛和最近原文保留；高级设置默认收起。名称和图标与
SuperLcm 后台一致，设置为全局共享，运行中的压缩插件自动应用。

## 全局接入

从 [安装包](RELEASE.md) 安装 SuperLcm，运行 `superlcm web`。打开「接入」中的
 dsh harness 卡片，点击「接入」，从其现有供应商和模型下拉列表中选择压缩模型，
再点击「安装并启用 SuperLcm 压缩」。这是一次全局接入，无需选择 web、acp 等内部启动方式，
也无需曾经安装 dsh-superlcm。完成后重新加载 dsh harness；更新时点击「更新接入」。

模型目录读取启用的 DSH 原生适配器及本机已安装的模型目录，合并各处已有配置。
同一供应商有不同账号或接口配置时会保留为不同选项，不混用凭证；接口相同的
模型列表会汇总。目录只返回供应商名称和模型名称、编号，密钥不进入浏览器。
读取目录不调用生成模型，实际生成压缩摘要会使用所选模型的调用额度。

全局设置写入 `DSH_HOME/cordis.patch.yml`。它由 DSH 在各启动配置之后应用，
因此现有及之后新增的启动方式均可接入同一会话库。插件的本地发行副本与 DSH
已有运行时依赖相连，无需为每种启动方式重复安装包。原聊天模型和供应商配置
不变；SuperLcm 插件单独调用选定的压缩模型，不另起第二套摘要写入器。
迁移旧接入时只停用旧压缩及归档入口，保留旧插件文件、索引和原文，退出现役的旧安装记录移入配置备份，并将正在使用的压缩参数迁移为全局设置。
所有配置修改先备份，验证失败会恢复；并发改动不会被静默覆盖。

接入同时检查已声明的智能体预设。预设里的默认压缩及工具输出裁剪退出活动配置，
预设继承全局 SuperLcm 压缩服务，避免 `pi-both` 等预设绕过后台门槛和模型设置。
预设的工具、提示词及模型选择保留。后来安装或修改的预设若另带压缩服务，需要再
管理接入；检查接入会明确报告这种冲突，不把它误标为已经全局接管。

DSH 的轨迹是按事件写入时间排列的审计记录，摘要事件因此可能出现在底部。
发送给模型的顺序由记录中的替换操作决定，摘要留在被替换内容的位置，后面接
近期原文；不能把轨迹页面的位置当成实际请求的位置。

DSH 只需加载一个 `superlcm` 组件，插件名称为 SuperLcm，使用统一图标。
压缩、共享归档、设置页面由这个组件在内部装载，用户无需分别安装三份插件。
旧的独立压缩和归档配置在更新时退出活动配置，原文与索引不删除。
本地副本位置由安装程序按当前用户的 DSH 和 SuperLcm 目录生成，不依赖作者的用户名
或地址；配置通过包名解析组件，普通插件列表不会把本机绝对路径当成名称。

命令行先查看已有供应商及模型，再明确选择并安装：

```sh
superlcm setup dsh
superlcm setup dsh --provider <供应商编号> --model <模型编号> --apply
```

同名供应商存在多份配置时，用预览中的 `ref` 指定 `--provider-ref <ref>`，
避免选择含糊。模型必须出现在已有目录中；不能靠填写名称创造未配置供应商。

所有载体共用当前 SuperLcm 控制台的会话库，默认 `~/.superlcm-claude`，自定义
存储目录也会明确写入全局接入配置。旧的 `DSH_SUPERLCM_DB` / `DSH_LOSSLESS_DB`
若指向别的数据库，需先取消；插件会拒绝静默另开一个会话库。

## 后台状态

压缩采用“分批准备、一次切换”。旧内容在后台按工具调用的完整边界生成摘要，
原文批次在后台形成一级摘要，同层积累到一组时继续形成更高层摘要。
旧的已提交摘要和本次新摘要共同受「摘要总预算」约束；超过预算时允许合并不同层级，
也允许继续精简一个过大的摘要，不必等满四个同层摘要。预算为 0 时自动取每批处理量
和压缩门槛一半中的较小值。例如门槛 260K、每批 64K，则摘要总预算自动为 64K。
摘要树及所有原文完整归档；主上下文只采用覆盖选区的高层摘要，不重复放入其子摘要。
准备期间主对话的原文和摘要位置不变。达到所设置的压缩门槛时固定本轮可压范围，
准备好该范围后一次替换；之后新增的内容留待下一轮，不继续追赶而无限推迟提交。
每次替换同时包含旧摘要和新摘要，避免只压新原文却留下越来越大的旧摘要前缀。
最近原文按设置的目标词元预算保留，选区根据最近真实模型用量校准 DSH 的文字估算，
避免中文被按四个字符一个词元低估。仅在预算为零时使用高级设置的条数限制。
工具调用保持完整；如果再保留一组旧调用会超预算，压缩这组调用，允许近期原文略低于
目标。最新一组调用本身超预算时仍完整保留。数值为校准估算，实际以模型回执为准。

切换本身会改变请求内容，供应商可能需要重建缓存，不能承诺零缓存损失。
这一策略减少小幅压缩反复切换的次数；后台摘要未就绪时继续保留原文，
不会阻塞主对话等待模型，也不会把失败标记成压缩完成。

后台模型请求使用独立、稳定的会话标识，与主对话和其他会话分开，避免代理把后台
摘要模型记成主对话的新模型并清除旧推理状态。原文归档仍归属真实主会话。
压缩门槛是允许提交已准备摘要的起点；硬上限是选区的紧急保护条件，允许放宽部分
保留和摘要合并限制，并非每次到门槛先替换一小块、再等硬上限替换另一轮。
摘要尚未完成时，两种压力都不会提交半成品；真正的模型溢出错误可尝试提交完整
就绪结果，但不会在前台等待摘要或截断原文冒充成功。

控制台展示全局接入和实际压缩状态，每 5 秒更新。引擎和归档插件回报进程、
已加载版本及阶段；配置保存与实际运行分开显示。后台摘要就绪可能仍需等待
压缩门槛才替换上下文，因此「摘要就绪」和「已替换上下文」是两个阶段。
运行状态不保存密钥、提示词或模型错误正文。

## 双向接续

dsh harness 中说“通过 SuperLcm 接续 #df671”，使用 `lcm_continue` 读取 Claude、
Codex 等工具的摘要和最近原文。其他工具中也用相同命令接续 dsh harness 对话。
`lcm_find` 支持 `harness: "dsh"`，`lcm_outline` 查摘要，`lcm_read` 查完整原文。
原 dsh harness 摘要标记使用的 `lcm_grep`、`lcm_describe`、`lcm_expand` 等工具保留。

启动后，插件从 dsh harness 官方会话读取接口补录已有和当前会话；每次事件后增量归档。
原始 dsh harness 事件完整保存在可移植记录的 `event` 字段，记录序号等于原事件序号。
每个事件只追加一次；重复事件对照摘要值，内容变更或序号断裂会暂停归档并告警。
索引和文件复制在一个本机后台进程执行，不卡住模型的每次事件提交。
DSH 投影的单条记录最多 4 MiB；超限会明确告警而不会截掉原文。通用会话读取器的单条上限为 32 MiB，以支持 Codex 的大型压缩记录。

旧索引 `~/.dsh/SuperLcm/lcm.sqlite` 和
`~/.dsh/lossless-context/lcm.sqlite` 以只读方式迁入共享库，旧库原地保留。
仅已成功提交且所有引用事件已归档的摘要进入共享目录；未提交压缩不会冒充成功。
dsh harness 摘要选择的原事件可能不连续，目录会给出准确 `source_records`，范围只表示
查阅边界，不能理解为范围内所有事件都已概括。

代码、包和配置可以预先验证。正在运行的 dsh harness 需要重启后才加载更换后的插件；
本机运行服务的重启依照工作区规则单独取得明确授权。

## 导入历史会话

在 SuperLcm 后台「接入 → dsh harness → 导入历史对话」选择本机已有的会话。
通过 DSH 的持久化读取接口读取压缩记录，保留完整原文、工具调用和工具结果，
同步可验证的已有压缩摘要，不调用模型，也不修改 DSH 原始会话文件。重复导入
不会增加重复记录；接入后，新消息继续追加到同一个共享档案，可由其他工具接续。

113 项基础测试、20 项 DSH 运行时测试通过；V9 主线程与顾问的真实记录回放
验证分层摘要准备、阈值固定范围和一次提交，回放使用本地确定性摘要，
不把回放结果当作真实模型的摘要质量或缓存测量。

12:10 的 V9 顾问真实压缩只发生一次上下文替换（记录 4425），覆盖范围
2857–4230，包含旧摘要及两批新原文，提交第三级摘要。压缩前最后一次
成功请求输入 259,407 个词元，随后输入 90,595，减少 168,812（约 65.1%）；
第一请求缓存 25,600（28.3%），第二请求输入 91,482、缓存 90,496（98.9%）。
代理在压缩后同时切换了提供方，不能把第一请求的全部缓存损失单独归因于压缩。

原记录在本机实际 DSH 会话投影与词元计量器中重放，验证部署后至该提交仅
有一次替换。摘要总量校准估算 27,294，低于自动 64K 预算；近期原文估算
47,292，包含完整工具边界及后台准备期间新增内容。提交前本机计量约
266,513，和供应商记录的请求输入是不同指标，不直接混算压缩比例。
摘要树从原始记录重建为第三级，无缺失子节点、无重建错误；原文完整保留。
