# dsh harness 接入与压缩

默认接入只归档原始事件、生成后台摘要并提供查询。DSH 使用自己的原生压缩；后台摘要写入 SuperLcm 档案，不替换聊天上下文。原文和工具结果完整保留，导入历史不调用摘要模型。

## 入口

SuperLcm 顶部导航为「对话 → 接入 → 压缩 → 设置」。

- 「接入 → dsh harness」：接入、更新、取消接入、导入历史、选择后台摘要 API。
- 「压缩 → dsh harness」：SuperLcm 的可选压缩接管开关、压缩模型、门槛、原文保留和高级参数。默认关闭；这些参数只用于开启接管后的 SuperLcm 引擎。
- DSH「插件 → SuperLcm」：仅显示「后台设置」，点击直接进入 SuperLcm 的 DSH 压缩页。
- 「设置」：公共摘要粒度、API 模型、外观和存储等。默认底层摘要原文目标约 20,000 个估算 token，每四段合并；与压缩接管独立。

## 全局接入

安装 SuperLcm，运行 `superlcm web`，在接入页管理 dsh harness。默认接入不需要选择压缩模型。更新或接入后重新加载 DSH；配置先备份，通过宿主自身的配置解析与 `--dump-config` 验证，保留聊天模型和原生压缩参数。所有启动方式共用同一个 SuperLcm 档案。

```sh
superlcm setup dsh
superlcm setup dsh --apply
```

取消接入撤销 SuperLcm 入口，恢复原生压缩，已有档案和摘要保留。更新或重新接入也回到默认后台摘要模式，不自动开启接管。

## 可选接管

在「压缩 → dsh harness」明确开启并保存。压缩模型来自 DSH 已配置的适配器和模型目录；目录查询不调用生成模型，不向页面返回凭据。压缩摘要会使用所选模型额度；聊天模型和后台摘要 API 不跟着改变。

首次开启会捕获各现有启动方式的原生压缩政策，停用它们的直接原生压缩入口，并安装唯一的压缩所有者。预设里的私有压缩域继承这个服务，工具、提示词与聊天模型保留。第一次安装接管后需要重新加载 DSH；页面在实际运行时确认前显示「等待应用」。确认要求版本、设置 revision、实际开关和同进程归档组件匹配。

关闭接管后，所有者加载真正的 DSH 原生压缩实现，恢复捕获的原生门槛、保留量和模型政策。损坏、缺失的控制文件及接管初始化失败也回到原生保护，不把失败的接管报告为已应用。重新启用插件只能恢复归档，不能自行开启接管。

之后新增的启动方式如果尚未捕获原生政策，保留直接原生压缩，不挂载第二个压缩引擎；重新接入并按需开启接管。并发配置改动会拒绝保存，验证失败按内容核对后回滚，避免覆盖用户正在编辑的配置。

DSH 轨迹按事件发生时间排列；摘要事件所在位置并不能说明实际发送给模型的上下文顺序。压缩接管的机制与历史验证见 [DSH 压缩优化](DSH-OPTIMIZATION.md)、[原生回退](DSH-NATIVE-FALLBACK-0.5.13.md)。这些结构与运行时测试不保证模型摘要质量；任务判断和关键细节仍应查回原文。

## 后台地址

本机默认后台端口为 8791。后台启动时记录实际端口，DSH 链接使用浏览器当前主机和后台端口，不转发 DSH 登录参数。远程部署使用不同域名或路径时，在 DSH 进程环境设置 `SUPERLCM_CONSOLE_URL=https://example.com/console`；仅支持不含账号密码或查询参数的 HTTP/HTTPS 地址。监听范围和后台访问控制不会因此扩大。
