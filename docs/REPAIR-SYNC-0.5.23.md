# 完整版与 DSH 独立版修复同步

完整版维护 Claude Code、Codex、Hermes、Pi 和可选 DSH 接入。DSH 独立版只使用 DSH 供应商、模型、数据库和插件设置页。两者单独安装、发布和保存数据。使用独立版时，不再为同一个 DSH 启用完整版接入。

## 本轮同步范围

完整 SuperLcm 0.5.23 对齐独立版 0.5.26 的旧格式读取规则：保留全部 Zstandard 帧，验证源文件身份与版本，原文件只读。编号断裂、重复或交错的记录按物理顺序保留，原编号始终保留在事件内。宿主将断序包装为迁移不支持时，也校验整份文件后恢复。

两版都优先读取活动会话已经接受的不可变事件，避免初次挂载时读到未落盘的磁盘日志。来源头只允许缺失的继承深度和预设信息补齐，冲突来源不能混同；存储版本与对话身份分别比较。

完整版使用现有共享原文查询工具和 JSONL 档案。恢复记录的 `dsh_archive` 明确给出 `ordinal`、`sourceSeq`、`sourceRow` 和 `sequenceMode`。`historical_archive` 说明来源版本、完成状态和位置模式。完整压缩源字节另存入私有数据库。已有档案前缀须逐条一致；不同来源、损坏行、当前格式文件存在或源文件中途变化均明确拒绝。分批索引失败时保存原文并标明未完成，成功完成后才确认归档。

旧格式档案只供原文检索，停止摘要计划并隐藏不能对应当前格式的旧摘要树，不把旧日志变成活动上下文。正常 DSH、Claude Code、Codex、Hermes、Pi 的接入与已选参数保持原样。独立版继续使用自己的 SQLite 原文与 DSH UI。

## 已完成的验证

- 完整版常规测试 249 项，DSH 运行时测试 70 项。
- 独立版 71 项测试及 macOS 官方安装升级验证。
- 真实旧日志共 52,695 条事件，完整版隔离回放中逐条内容、原编号和压缩原文一致。
- 真实 DSH 持久化供应器的旧日志列表与导入接口、后台工作进程和普通召回工具均有回归。正常 DSH 首次挂载、冷历史、共享会话接续继续通过。
- 本轮没有 Windows 实机测试，GitHub 自动测试保持关闭。

## 维护约定

Claude 接管的修复只进入完整版，DSH UI 的修复只进入独立版。涉及旧日志读取、原文保护、来源身份或 DSH 压缩算法的共性修复，要同时核对两仓库并分别测试，不以版本号相同作为同步证据。本轮修复及适用范围在此列明。
